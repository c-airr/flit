# flit v1 (spec steps 5–8) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reactive state, pointer input with `Pressable`/`Button`, the real Gio
backend and `examples/counter`, plus Linux CI. This is the end of v1.

**Architecture:** `Signal[T]` subscribes the composite node that reads it and
marks it dirty on `Set`; `App` drains a `Post` queue, rebuilds dirty nodes
shallowest first, lays out and paints. `Pressable` keeps hover/pressed state
in its node and rebuilds its child through a function. `backend/gio` turns Gio
events into `ui.PointerEvent`s and the `draw.List` into Gio ops, measuring
text exactly the way it draws it.

**Tech Stack:** Go 1.26.2, Gio v0.10.3, Inter 4.1, llvm-mingw clang (for `-race` only).

**Spec:** `docs/superpowers/specs/2026-10-04-flit-v1-design.md` (amended 2026-10-05).
Tasks 1–2 = spec step 5, tasks 3–4 = step 6, tasks 5–6 = step 7, task 7 = step 8.

## Global Constraints

- Module `github.com/c-airr/flit`. Code, comments, commit messages in English.
- `ui` and `draw` must not import Gio and must not use cgo:
  `GOOS=linux go vet ./draw/... ./ui/...` passes.
- All sizes are dp (logical pixels, `float32`), font sizes too; the Gio
  backend pins `PxPerSp = PxPerDp`.
- `draw.FormatVersion` stays 1 (the StrokeRect "inside" rule is a
  clarification made before any renderer shipped).
- Widget API: short constructors, chained value-receiver options returning a
  copy, types named `XxxWidget`.
- Comment non-obvious Go for a C++ reader (generics, goroutines, mutexes,
  closures, interfaces).
- Every task ends green on: `go test ./...`, `go vet ./...`,
  `GOOS=linux go vet ./draw/... ./ui/...`, and, for tasks that touch `ui`,
  `CC=clang CGO_ENABLED=1 go test -race ./ui/...` with llvm-mingw's `bin`
  directory on `PATH`. Then commit, ending the message with the session's
  attribution lines.
- No push to GitHub without the author's OK.

## Review Focus

1. A click handler that removes its own Pressable (disposed while pressed or
   hovered): no panic, no click on the dead node, cursor back to default (Task 3).
2. A build function that calls `Set`: no infinite loop inside one frame; the
   work waits for the next frame and `NeedsFrame()` says so (Tasks 1–2).
3. `Post` from many goroutines at once: nothing lost, no data race under
   `-race` (Task 2).
4. Press on one Pressable and release outside it or on another one: no click (Task 3).
5. A minimized window (viewport 0×0) and pointer events before the first
   frame: no panic (Tasks 2–3).

**Interfaces:**

- Produces:

    `BuildWidget` implements it. `childWidgets`, `layoutNode` and `paintNode`

  - `type dependency interface{ unsubscribe(n *node) }`; package-level
    `var currentBuild *node`.

- [ ] **Step 3: Implement.**
  - A composite build (in `childWidgets`): unsubscribe all `n.deps`, clear
    them, set `n.dirty = false`, save `currentBuild`, set it to n, call
    `w.build(n, &Ctx{env: e})`, restore `currentBuild` with `defer`.
  - `Get`: if `currentBuild != nil`, add it to the subscribers (once) and
    append the signal to the node's `deps`. `Set`: store, then `markDirty`
    every subscriber. `Update(fn)` = `Set(fn(Get()))` but must not subscribe.
  - `dispose` also unsubscribes and clears `deps`.
  - `rebuildDirty`: take the current `t.dirty` slice and set `t.dirty = nil`
    (new marks go to the next round), sort the taken nodes by `depth`
    ascending (`slices.SortFunc`), and for each node that is still dirty and
    not disposed call `n.update(n.widget, &t.env)`.
